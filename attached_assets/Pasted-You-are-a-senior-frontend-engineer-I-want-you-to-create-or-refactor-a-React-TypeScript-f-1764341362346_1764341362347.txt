## 3. Routing & Layout Behavior

Implement routing with **React Router v6**:

- `main.tsx`
  - Wrap the app in `<BrowserRouter>`.
  - Render `<App />`.

- `App.tsx`
  - Wrap children in all context providers:
    - `<AuthContextProvider>`
    - `<ProfileContextProvider>`
    - `<ProjectContextProvider>`
    - `<NotificationContextProvider>`
  - Define a main layout:
    - **Public layout**: simple navbar + main content + footer using Public components.
    - **Private layout**: sidebar navigation + top bar (user info + notifications) + main content.
  - Use:
    - `<PublicRoutes />` for: `/`, `/about`, `/contact`, `/terms`, `/privacy`, `/sign-in`, `/sign-up`, `/forgot-password`, `/otp-verification`, `/reset-password`.
    - `<PrivateRoutes />` for protected paths: `/dashboard`, `/projects`, `/projects/:id`, `/offers`, `/contracts`, `/payments`, `/profile`, `/notifications`.

- `PublicRoutes.tsx`
  - Define all public & auth routes and render their respective pages.

- `PrivateRoutes.tsx`
  - Use `useAuth()` to check `isAuthenticated`.
  - If not authenticated → navigate to `/sign-in`.
  - If authenticated → render private layout and nested routes.

## 4. Core Frontend Logic (high level, no real backend)

### Auth

- `AuthContext.tsx` + `useAuth.ts`
  - Holds:
    - `user` (id, email, role: "skill_giver" or "skill_searcher")
    - `token`
    - `isAuthenticated`
  - Methods:
    - `login(credentials)`
    - `logout()`
    - `loadCurrentUser()`
  - Persist token in `localStorage` for now.

- `authService.ts`
  - Functions (for now return Promises with mocked data):
    - `login(email, password)`
    - `register(payload)`
    - `requestPasswordReset(email)`
    - `verifyEmailOTP(email, code)`
    - `verifyResetOTP(email, code)`
    - `resetPassword(payload)`
    - `getCurrentUser()`

- Auth pages (`SignInPage`, `SignUpPage`, `ForgotPasswordPage`, `OTPVerificationPage`, `ResetPasswordPage`) use the corresponding components in `components/Auth/` for the forms and call `authService` then update `AuthContext`.

### Profiles

- `ProfileContext.tsx` + `useProfile.ts`
  - Stores:
    - current profile data for the logged-in user (Skill Giver or Skill Searcher).
  - Methods:
    - `loadSkillGiverProfile()`
    - `updateSkillGiverProfile(data)`
    - `loadSkillSearcherProfile()`
    - `updateSkillSearcherProfile(data)`
    - `uploadCV(file)` (just mocked for now).

- `SkillGiverProfilePage` / `SkillGiverEditPage`:
  - Show and edit personal info, skills, experience, education, certifications, personal projects.

- `SkillSearcherProfilePage` / `SkillSearcherEditPage`:
  - Show and edit company profile (company name, industry, website, contact, bio).

- Use subcomponents from `components/Profile/` to build these pages.

### Projects, Offers, Contracts, Payments, Notifications

Implement basic but realistic UIs:

- `ProjectContext` + `useProjects`:
  - Hold a list of projects and selected project.
  - Methods:
    - `loadSkillGiverProjects()`
    - `loadSkillSearcherProjects()`
    - `getProjectById(id)`
    - `createProject(data)` (called from `AddProjectPage` using `AddProjectForm`).
  - Use `ProjectCard` and `StageTaskCard` in project pages.

- `OffersListPage` / `OfferDetailPage`:
  - Render mock offers with statuses (Pending, Accepted, Rejected).
  - `offersService` methods: `getOffersForUser()`, `acceptOffer(id)`, `rejectOffer(id)`.

- `ContractsListPage` / `ContractDetailPage`:
  - Show mock contracts (status: Draft, Sent, Signed).
  - `contractsService` with methods: `getContractsForUser()`, `signContract(id)`.

- `SkillGiverInvoicesPage` / `SkillSearcherPaymentsPage`:
  - Show mock invoices/payments.
  - `paymentsService` with methods: `getInvoicesForUser()`, `getPaymentsForUser()`.

- `NotificationContext` + `useNotifications`:
  - Store notification list and unread count.
  - Methods:
    - `loadNotifications()`
    - `markAsRead(id)`
    - `markAllAsRead()`
  - `NotificationsList` + `NotificationItem` display them.

All services (`projectService`, `offersService`, `contractsService`, `paymentsService`, `notificationsService`) should be thin wrappers around the `api` Axios instance, but for now can return mocked data.

## 5. API & Utils

- `services/api.ts`
  - Create an Axios instance with:
    - `baseURL = import.meta.env.VITE_API_BASE_URL || "http://localhost:3000"`
    - Request interceptor to attach `Authorization: Bearer <token>` from `AuthContext` or `localStorage` (if token exists).
    - Response interceptor to handle 401 (unauthorized) by logging out and redirecting to `/sign-in`.

- `utils/validation.ts`
  - `isValidEmail`, `isStrongPassword`, `isValidPhone`.

- `utils/formatters.ts`
  - `formatDate`, `formatCurrency`, and helpers for status labels.

- `utils/constants.ts`
  - Status arrays and enums for:
    - Projects, stages, tasks
    - Offers
    - Contracts
    - Invoices & payments
    - Roles and user types (`"skill_giver"`, `"skill_searcher"`).
